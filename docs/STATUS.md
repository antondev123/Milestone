## Gotchas
- `serveNext({peek:true})` must never touch live progress: the store returns the same object every call, so an uncommitted mutation is still a mutation. Peek clones first; keep it that way when adding helpers.
- ElevenLabs pre-tool speech closes the agent's turn: a tool result that lands after the filler finishes is never spoken. Keep `pre_tool_speech: "off"` on every tool; the soft-timeout filler is the only safe one.
- `onModeChange → listening` fires between TTS chunks too. Any "the agent has finished" logic must gate on the utterance's minimum speaking time (`GATE_WPM`), not on the mode alone.
- Stage demo: it fires only for a Listen trip while the cursor still stands at 2.5 part 1, and only once. Reading or studying past that point first, or an earlier demo run, disarms it; the trip then just carries on past part 2 like any open-ended trip → say "I'm done", run `npm run demo:stage`, reload. `npm run demo:reset -- --seed` does not arm it.
- Hosting: Fly (one machine + volume) keeps the file store. Vercel/Netlify would fall back to memory per instance and drift between requests; not used.
- Grading latency: Sonnet 5 at low effort is ~4 s; the 2.5 s "One moment." filler covers it. If it drags, switch ANTHROPIC_MODEL to claude-haiku-4-5 for grading only. `ask` uses ANTHROPIC_ASK_MODEL (default claude-sonnet-5, low effort, ~2–4 s; set claude-haiku-4-5 to shave a second). A question asked *while a question is open* costs both calls back to back (classify+grade, then ask), ~6–8 s: "One moment." then "Let me check." cover it, but watch it in rehearsal.
- The in-app browser blocks the microphone. `/learn/voice?text=1` runs the real agent without audio (it reads on its own; no text box on the Dial, it is hands-free), or use Chrome for the mic. For typed commands use Read mode.
- Restart `npm run dev` after editing .env.local; Next does not hot-reload env.
- Study read-aloud: the word highlighter is a rAF loop that only the `<audio>` `play` event starts. Anything that re-binds the listener effect in `useReadAloud.ts` mid-playback cancels the loop, so `loadBlock`'s deps must stay stable (speed lives in a ref) and the effect resumes the loop itself if the element is already playing. Fixed 2026-09-18 after the speed pill froze the highlight.
- Client tools (browser) vs webhook tools (dashboard): the component uses client tools so localhost works without ngrok. Configure them as type Client in the dashboard.
